# 남식당 식단 경험 개선

## 목적과 결정 권한

남도학숙 사생이 은평관·동작관의 원하는 날짜 식단을 빠르게 읽는 생활 도구다. 사용자는 디자인 결정, 구현, 검증, 중간 커밋, 스크린샷을 포함한 PR 작성을 모두 위임했다. 이 문서의 색상·배치·문구는 그 위임에 따른 구현자의 결정이다.

## 현재 문제

- 흰 카드 안에 다시 카드가 중첩되어 모바일에서 실제 식단의 폭이 좁다.
- 날짜 버튼은 스크린리더 이름과 선택·비활성 상태 표현이 부족하다.
- 오늘로 이동하는 버튼이 조건부로 나타나면서 화면 높이가 바뀐다.
- 네트워크 오류가 나면 화면에서 다시 시도할 수 없다.
- 미등록 식단, 로딩, 오류의 구분과 다음 행동이 명확하지 않다.
- 서비스 정보는 전체 화면을 차지하며 링크와 닫기 버튼의 접근성을 개선할 여지가 있다.

## 접근법 비교

1. 기존 크림·그라데이션의 부분 수정: 변경량은 작지만 중첩 구조와 약한 정보 위계가 남는다.
2. 민트 중심의 식단 도구: 기존 로고를 유지하고 관·날짜·식단의 순서를 정돈한다. 작은 화면의 읽기 폭을 넓히고 데스크톱에서 세 끼를 나란히 보여준다. **선택한 방향**이다.
3. 음식 사진을 강조하는 콘텐츠 서비스: 매력적인 이미지는 만들 수 있지만 실제 식단에 없는 사진이 메뉴로 오인될 수 있고 핵심 조회를 늦춘다.

## 시각 언어

- 기존 남식당 이름과 로고를 유지한다. 화면의 개성은 민트 선택 표시와 차분한 식단 배치에 집중한다.
- 주요 색: 배경 `#F5F8F7`, 표면 `#FFFFFF`, 본문 `#182D29`, 보조 본문 `#5D706B`, 브랜드 `#087F70`, 선택 배경 `#E5F4EF`.
- 아침·점심·저녁은 동일한 구조와 서로 다른 절제된 아이콘 색으로 구분한다. 색과 함께 반드시 한글 이름을 쓴다.
- 한국어는 플랫폼 기본 고딕 계열을 사용한다. 외부 폰트 로딩 없이 시스템의 글자 확대를 따른다.
- 기본 간격은 4/8 단위, 조작 최소 크기는 48, 카드 모서리는 20, 컨트롤은 12~16으로 역할을 구분한다.
- 원시 값 → 의미 토큰 → 컴포넌트 스타일의 순서로 `theme.ts`에 모은다.
- 불필요한 그라데이션, 큰 그림자, 자동 애니메이션, 장식용 카운트와 마케팅 문구를 제거한다.

## 화면과 동작

```text
남식당 / 남도학숙 식단                         서비스 정보

오늘의 식단                           [동작관 | 은평관]
관별 하루 세 끼 안내

10월 25일 일요일                    [이전] [다음] [오늘]
[날짜] [날짜] [선택된 날짜] [날짜] [날짜] ...

[아침 / 메뉴 목록]   [점심 / 메뉴 목록]   [저녁 / 메뉴 목록]

식단은 학숙 사정에 따라 변경될 수 있어요.       서비스 정보
```

- 모바일에서는 관 선택을 제목 아래에 놓고 세 끼를 세로 배치한다. 넓은 화면에서는 세 끼를 같은 폭으로 배치한다.
- 현재의 5/7일 날짜 목록과 ±3개월 조회 제한을 유지한다. 선택·오늘·주말·비활성을 텍스트와 의미 속성으로 구분한다.
- 날짜 변경 이후에도 오늘 버튼의 위치는 유지한다. 선택 날짜와 관을 식단 영역에 명시한다.
- 로딩 중에는 상태 문구와 식단 카드 형태의 정적 자리표시자를 표시한다. 동작 없는 반복 애니메이션을 추가하지 않는다.
- 조회 오류에는 현재 관·날짜를 유지하는 다시 불러오기 버튼을 제공한다. 재시도와 관/날짜 변경이 겹쳐도 이전 응답이 화면을 덮지 않아야 한다.
- 미등록은 식사 미제공으로 단정하지 않는다. 아직 등록된 식단이 없다는 사실과 다른 날짜를 선택할 수 있다는 안내를 제공한다.
- 서비스 정보는 닫기·Escape·Android 뒤로가기와 키보드 접근을 지원한다. 기존 개발자·메일·GitHub 목적지는 유지한다.
- 모든 컨트롤에 역할·접근성 이름·선택/비활성 상태와 포커스 표시를 제공한다. 장식 아이콘은 읽기 순서에서 제외한다.

## 제약과 제외 범위

Expo 54, React Native 0.81, React 19를 유지한다. 웹 전용 UI 프레임워크로 교체하지 않는다. Firestore 스키마, 환경 변수, 로컬 날짜, 관 저장 키와 기존 조회 제한을 유지한다. 식사 시간·알레르기·영양 정보는 근거 데이터가 없어 생성하지 않는다. 운영 배포·병합은 수행하지 않는다.

## 검증과 인수 조건

- 기존 99개 테스트, 기존 핵심 모듈 100% 커버리지, 타입 검사, Expo 웹 내보내기를 통과한다.
- 오류 → 재시도 → 정상 식단, 관/날짜 전환, 오늘 복귀, 정보 열기/닫기를 실제 렌더링에서 확인한다.
- 375px 모바일, 태블릿, 1440px 데스크톱 및 가로 화면에서 가로 넘침·잘림·포커스 표시를 확인한다.
- 비교용 스크린샷은 실제 렌더링 결과를 기록한다. 테스트용 식단을 사용하면 실제 운영 식단과 혼동하지 않도록 캡션에 명시한다.
- Gitflow: `feature/menu-experience` → `develop`. 변경 단위로 커밋하고 PR에 목적, 변경점, 전후 이미지, 검증, 플랫폼 한계를 설명한다.

## 디자인 스킬 적용

`design`, `frontend-design`, `ui-ux-pro-max`, `design-system`, `ui-styling`, `brand`를 사용했다. UI 검색 데이터의 패션 팔레트와 음식 주문용 랜딩 페이지 추천은 이 서비스와 맞지 않아 채택하지 않았다. 기존 브랜드와 식단 조회 과제에 맞춘 자체 색상·위계를 적용한다. `ui-styling`은 접근성·반응형·토큰 원칙만 적용하고 웹 전용 shadcn/Tailwind 의존성은 도입하지 않는다. 사진·배너·발표자료 생성은 이 조회 화면에 도움이 되지 않아 범위에 포함하지 않는다.
